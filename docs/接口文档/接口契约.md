# 接口契约

> 平台对外接口：REST（契约⑥）+ SSE 事件流（契约④）。所有类型为平台自定义，框架类型不越过编排层（防火墙原则）。
> 关联：[前端设计](../前端文档/前端设计.md)（事件→UI 映射的消费方） · [数据库设计](../数据库设计/数据库设计.md)（持久化 schema） · [后端设计](../后端文档/后端设计.md)

## 1. 通用约定

- Base URL：`/api/v1`；鉴权：`Authorization: Bearer <JWT>`（P3 前 dev 模式可免）；
- 租户隔离：JWT claims 携带 `tenant_id`，所有资源按租户过滤；
- 分页：`?limit=&cursor=`（keyset 分页，cursor 为Opaque 串）；
- 错误响应统一：

```json
{ "error": { "code": "not_found", "message": "session not found", "details": {} } }
```

### 错误码表

| code | HTTP | 含义 |
|---|---|---|
| `unauthorized` | 401 | 未认证/令牌过期 |
| `forbidden` | 403 | 越权访问他租户资源 |
| `not_found` | 404 | 资源不存在 |
| `quota_exceeded` | 429 | 租户配额/频控 |
| `session_busy` | 409 | 同会话已有活跃 run |
| `run_not_resumable` | 409 | run 不处于挂起状态 |
| `ticket_expired` | 410 | 审批工单超时（按 deny 处理） |
| `upstream_error` | 502 | 供应商错误（透传 message） |
| `internal` | 500 | 内部错误 |

## 2. REST 端点（契约⑥）

### 2.1 会话

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/sessions` | 创建会话。body: `{ "title?": str, "model": str, "sandbox_image?": str }` → `201 Session` |
| GET | `/sessions` | 会话列表（分页）→ `Session[]` |
| GET | `/sessions/{sid}` | 会话详情（含 `session_state` 摘要）→ `Session` |
| PATCH | `/sessions/{sid}` | 改标题/模型/归档 |
| DELETE | `/sessions/{sid}` | 归档删除（软删） |

`Session`：`{ id, tenant_id, title, model, created_at, updated_at, archived, state_summary }`

### 2.2 消息与 run

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/sessions/{sid}/messages` | 历史消息（事实源，分页、倒序）→ `Message[]` |
| POST | `/sessions/{sid}/messages` | 发送用户输入并启动 run。body: `{ "content": [ContentBlock] }` → `202 { "run_id": str }`；同会话已有活跃 run → `409 session_busy` |
| GET | `/runs/{run_id}` | run 状态：`{ id, session_id, status: queued|running|interrupted|succeeded|failed, usage_total, error? }` |
| POST | `/runs/{run_id}/cancel` | 请求取消（协作式：下一轮次边界生效） |

`Message`：`{ id, run_id, role: user|assistant, content: ContentBlock[], created_at }`
`ContentBlock`：`{type:"text",text}` | `{type:"image",media_type,data}` | `{type:"tool_call",id,name,input}` | `{type:"tool_result",tool_use_id,content,is_error}`

### 2.3 审批（HITL）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/approvals?status=pending` | 待审批工单（跨会话，审批中心页数据源） |
| GET | `/approvals/{ticket_id}` | 工单详情：`{ ticket_id, run_id, session_id, items: ApprovalItem[], status, expires_at }` |
| POST | `/runs/{run_id}/approvals/{ticket_id}/decide` | 决策。body 见下 → 决策写表 + 入 resume 队列；已决/超时分别返回 409/410 |

决策请求：

```json
{
  "choices": [
    { "call_id": "a1", "approve": true },
    { "call_id": "a2", "approve": false, "reason": "nope" }
  ]
}
```

`ApprovalItem`：`{ call_id, tool_name, reason, risk_level, input_preview }`（即 interrupt payload，`gateway/approval.py::payload_for` 是唯一来源）。未覆盖的 call_id fail-closed 按拒绝处理；TTL 默认 30min。

### 2.4 事件流（SSE）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/sessions/{sid}/events` | `text/event-stream`。参数 `?after=<event_id>` 或请求头 `Last-Event-ID` 续传（服务端 XREAD Redis Stream 从该 ID 重放） |

SSE 帧格式：

```
id: 1712345678901-0        ← Redis Stream entry id（重连续传游标）
event: assistant_delta
data: {"text":"你"}

id: ...
event: run_finished
data: {"usage":{"input_tokens":13,"output_tokens":7,"total_tokens":20},"stop_reason_hint":"end_turn","error":null}
```

### 2.5 其他（按阶段开放）

| 阶段 | 端点 | 说明 |
|---|---|---|
| P2 | `GET /sessions/{sid}/state` | SessionState 工作记忆（goals/artifacts/work_log） |
| P3 | POST `/auth/login`、`/auth/refresh` | JWT 签发 |
| P3 | CRUD `/credentials` | 供应商凭证（写入即加密，响应永不回显明文） |
| P3 | GET/POST `/memories` | 语义记忆检索/写入（pgvector） |
| P4 | `/agents`、`/tasks`、`/teams` | 多智能体（swarm） |

## 3. SSE 事件契约④（九种，全集）

| type | payload | 触发点 | 前端行为（详见前端设计） |
|---|---|---|---|
| `assistant_delta` | `{text}` | agent 节点文本增量 | `streaming-text` 打字机追加 |
| `assistant_turn_complete` | `{message}` | 写穿发布（表→Stream 顺序） | 消息落定，替换流式缓冲 |
| `tool_started` | `{tool_name, tool_input}` | execute 节点 | `tool-chips`/任务行置"运行中" |
| `tool_completed` | `{tool_name, output, is_error, ui}` | execute 节点 | 卡片完成态；`ui` 渲染 diff/终端（永不进模型） |
| `compact_progress` | `{stage, detail}` | compact 节点 | 状态条"压缩中" |
| `approval_required` | `{ticket_id, items[]}` | runner 从 `__interrupt__` 提取 | `approval-card` 弹窗 + 审批中心角标 |
| `status` | `{message}` | 内核重试等 | 状态条提示 |
| `error` | （经 `run_finished.error` 或独立） | 终止性错误 | 错误 toast |
| `run_finished` | `{usage{input,output,total}, stop_reason_hint, error}` | finalize 节点 | 结束态 + usage 展示 |

保证：
1. **顺序**：同一会话事件按 Redis Stream 单调有序；`assistant_turn_complete` 晚于表写入；
2. **续传**：断线以 `Last-Event-ID`（Stream entry id）重放，不丢不重；
3. **审批闭环**：`approval_required` → 用户决策 → REST decide → resume → 后续事件继续同流。

## 4. 事件与内部数据结构的映射

```
engine 节点 emit(dataclass) ──translate()──► SSEEvent(type,payload) ──XADD──► Redis events:{session}
runner: __interrupt__.value ──────────────► SSEEvent("approval_required")
runner: values 快照 assistant 消息 ────────► SSEEvent("assistant_turn_complete")
```

翻译函数唯一实现：`engine/events.py::translate()`；九种类型常量 `SSE_EVENT_TYPES`。
