## 一、权限系统（permissions/）

### 1.1 目标布局

```
permissions/
├── engine.py       # PermissionEngine Protocol + RuleEngine 实现（evaluate）
├── rules.py        # PermissionRule 数据结构 + 三类匹配器（tool/path/command）
├── recipes.py      # 三配方的内置规则集（谨慎/标准/托管）
└── approval.py     # 审批工单（已实现，自 gateway/ 迁入）
```

### 1.2 决策流（在网关闸门④的位置）

```
闸门③ 校验通过后：
  resolved = resolver.resolve(raw_input, sandbox)        # 六.2 唯一路径解析器
  read_only = tool.is_read_only(parsed)                  # 按输入动态定级（ls vs rm 同工具不同级）
  decision = engine.evaluate(name, read_only, resolved, command, ctx)
      ├─ ALLOW           → 进 auto_run
      ├─ DENY(reason)    → refused 终态回执（"Permission denied for {tool}: {reason}"）
      └─ REQUIRE_CONFIRM → need_approval → tools_approval 节点 interrupt 工单
```

不变式：
- **P1 裁决只看规范化后的目标**：路径规则匹配 `resolved`（绝对化+沙箱根内 realpath），命令规则匹配 `command` 原文与首 token 展开；规则永远拿不到"模型原样的相对路径"；
- **P2 fail-closed**：未知工具/无法归类/规则加载失败 → 按 `DENY("no matching rule")`，绝不默认放行；
- **P3 决策可重放**：evaluate 纯函数（同一输入同输出），依赖只在入参里——节点重放安全。

### 1.3 数据结构

```python
RuleKind = Literal["tool_allow", "tool_deny", "path_allow", "path_deny", "cmd_allow", "cmd_deny"]

@dataclass(frozen=True)
class PermissionRule:
    kind: RuleKind
    pattern: str            # tool: 精确名或通配 "web_*"；path: glob（对容器内路径）；cmd: 首 token 或正则
    risk_level: str = "medium"   # low|medium|high（require_confirm 时透传给审批卡）
    priority: int = 100     # 小者优先
    enabled: bool = True

@dataclass(frozen=True)
class Decision:
    kind: Literal["allow", "deny", "require_confirm"]
    reason: str = ""
    risk_level: str = "medium"
    rule_id: str | None = None   # 命中的规则（审计用）
```

### 1.4 匹配顺序（第一条命中即返回）

```
1. deny 类规则（priority 升序）        —— 显式禁止最优先
2. allow 类规则（priority 升序）
3. 配方默认（recipe default，见 1.5）
4. 兜底 DENY("no matching rule")       —— P2 fail-closed
```

匹配器：
- `tool_*`：对工具名精确或 `fnmatch` 通配；
- `path_*`：对 `resolved.container_path` 做 glob（`/workspace/**` 围栏天然成立——resolver 已保证越界即 `PathEscape`，逃逸路径根本到不了这一步）；
- `cmd_*`：对命令行做两级匹配——首 token 精确/通配（`git`、`npm`），或整行正则（`^git\s+push\b`）；仅对声明 `executes_commands=True` 的工具有效。

### 1.5 权限配方（三选一，租户默认 + 会话覆盖）

| 配方 | 语义 | 内置规则集 |
|---|---|---|
| **谨慎** | 除工作区内只读外全部要批 | `path_allow /workspace/**` 仅当 `read_only=True` → ALLOW；其余一律 REQUIRE_CONFIRM(risk=high) |
| **标准**（默认） | 读自动、工作区写自动、危险命令与工作区外要批 | 读 → ALLOW；`path_allow /workspace/**`（写）→ ALLOW；`cmd_deny` 危险清单（`rm -rf /`、`sudo`、`curl|bash`、网络系工具在 --network none 下本已失效）→ DENY；其余写/命令 → REQUIRE_CONFIRM |
| **托管** | 只读外全批 | 读/写工作区 → ALLOW；工作区外路径 → DENY；命令 → ALLOW（受沙箱网络/文件系统兜底） |

配方的落点：`sessions.permission_recipe`（会话覆盖）+ `tenants.quotas['default_recipe']`（租户默认）。**否决**账户级角色→模型矩阵、自定义四轴存为默认（对齐 UX 文档 §七）。

### 1.6 与审批工单的衔接

`REQUIRE_CONFIRM` 的调用在网关 `plan()` 阶段进入 `ToolPlan.need_approval`，随后 tools_approval 节点经 `ApprovalService.ensure_ticket`（幂等键 `hash(run_id, sorted(call_ids))`）+ `interrupt(payload_for(...))` 挂起。决策链、TTL（30min → expired 按 deny 恢复）、fail-closed（未覆盖 call 视为拒绝）见[后端设计 §5](后端设计.md)。本层新增约定：**decision.reason 必须可读**——拒绝回执会原样喂给模型（"Permission denied for bash: workspace 外的写操作需要审批"），模型据此改道。

### 1.7 审计与规则存储

每次 evaluate 结果写 `audit_events(kind="permission_decision")`（含 rule_id、resolved 路径、命令摘要、decision）——审计只记录不阻断；租户可在 filter-table 里回放。规则存储 DDL（补入数据库设计）：

```sql
CREATE TABLE permission_rules (
    id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id  uuid NOT NULL REFERENCES tenants(id),
    scope      text NOT NULL DEFAULT 'tenant' CHECK (scope IN ('tenant','session')),
    session_id uuid REFERENCES sessions(id),          -- scope='session' 时必填
    kind       text NOT NULL CHECK (kind IN ('tool_allow','tool_deny','path_allow','path_deny','cmd_allow','cmd_deny')),
    pattern    text NOT NULL,
    risk_level text NOT NULL DEFAULT 'medium',
    priority   int  NOT NULL DEFAULT 100,
    enabled    boolean NOT NULL DEFAULT true,
    created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_rules_lookup ON permission_rules(tenant_id, scope, session_id, priority) WHERE enabled;
```

规则变更实时生效：RuleEngine 每 run 开始时按 (tenant, session) 拉一次并缓存于 `EngineDeps`（run 内不变——决策可重放）。

## 二、沙箱（sandbox/）

### 2.1 威胁模型与安全不变式

对手：**模型输出的工具参数**（可能含注入、越界路径、资源炸弹）。防线四层：网关闸门（本文 §一）→ 路径 resolver → 容器隔离 → 资源限额。

**S1 安全不变式（验收逐条对表）**：
- S1.1 所有工具执行只发生在沙箱容器内；引擎/网关进程**从不**直接执行模型指定的代码或命令；
- S1.2 容器 `--network none`：模型侧网络类工具（web_fetch 等）走宿主侧代理工具，不经容器；
- S1.3 容器非 root（uid 1000）、`cap-drop ALL`、`no-new-privileges`、自定义 seccomp（禁 ptrace/mount/namespace 类系统调用）；
- S1.4 文件访问只经 `resolver` 的 `/workspace` 映射（见 2.5），越界在 resolver 层即拒绝，容器内再兜底（挂载即边界）；
- S1.5 资源限额：`--memory 512m --cpus 1.0 --pids-limit 128 --read-only + tmpfs /tmp`——CPU/内存炸不伤宿主；
- S1.6 输出上限：单次 exec 捕获 ≤ `output_cap`（默认 1 MiB），超出截断并触发 spill（网关收尾 A）。

### 2.2 目标布局与接口

```
sandbox/
├── handle.py       # SandboxHandle Protocol（契约⑦）
├── docker.py       # DockerSandbox：aiodocker 实现
├── image/Dockerfile + jail.py    # 镜像与 jail 包装器源码
└── pool.py         # 生命周期管理（懒创建/空闲回收/销毁）
```

```python
class SandboxHandle(Protocol):
    session_id: str
    root: str                                     # 宿主侧工作目录
    async def exec(self, argv: list[str], *, cwd: str = "/workspace",
                   env: dict[str, str] | None = None,
                   timeout_s: float = 120.0,
                   output_cap: int = 1_048_576) -> ExecResult: ...
    async def read_file(self, container_path: str, *, cap: int) -> bytes: ...
    async def write_file(self, container_path: str, data: bytes) -> None: ...
    async def destroy(self) -> None: ...

@dataclass(frozen=True)
class ExecResult:
    exit_code: int
    stdout: str
    stderr: str
    truncated: bool
    duration_ms: int
```

工具实现方**只拿 `SandboxHandle`**，拿不到 docker 客户端；`read_file/write_file` 同样过 resolver（权限闸门④与执行共用 §一.2 的同一次 resolve）。

### 2.3 容器生命周期

```
会话首个工具调用 ──懒创建──► running ──空闲 >10min──► stopped（保留）
run 结束不销毁；会话归档 / 租户配额回收 / worker 关停 ──► destroyed（容器+匿名卷删除）
```

- 命名 `ch-sbx-{session_id[:12]}`，labels：`codeharness.tenant / .session / .created_at`（watchdog 兜底清扫孤儿）；
- 创建失败重试 2 次（退避 1s/3s）→ 仍失败 = 网关错误回执 `sandbox_unavailable`（工具错误喂回模型，run 不炸）；
- 复用语义：同会话顺序复用同一容器（状态残留是**特性**——`pip install` 后续调用可见）；并行 `parallel_safe` 调用在同一容器内并发 exec（容器进程隔离足够）。

### 2.4 容器规格（`docker run` 参数全集）

```bash
docker run -d --name ch-sbx-{sid}
  --network none \                 # S1.2
  --user 1000:1000 \               # S1.3
  --cap-drop ALL --security-opt no-new-privileges \
  --security-opt seccomp=ch-seccomp.json \   # 禁 ptrace/mount/unshare 等
  --read-only --tmpfs /tmp:rw,size=64m,uid=1000 \
  --memory 512m --cpus 1.0 --pids-limit 128 \
  --log-driver none \              # 输出走 exec 捕获，不落 docker log
  -v {host_workdir}:/workspace:rw \
  codeharness-sandbox:1.0 sleep infinity
```

### 2.5 文件系统与路径映射（与 resolver 协作）

- 宿主 `services/session_storage` 侧为每会话维护工作目录 `{data_root}/workspaces/{session_id}/`，bind mount 为容器 `/workspace`；
- `resolver.resolve()` 产出 `ResolvedPath(host_path, container_path)`：权限裁决与审批展示用 **container_path**（用户/模型视角一致），物理 IO 用 host_path——两侧映射是 resolver 的私有细节，不暴露给工具；
- 符号链接：resolve 阶段在宿主侧 realpath 后校验仍在工作目录内（逃逸=PathEscape）；容器内因只挂载 /workspace，逃逸面被二次压缩；
- 用户上传/大产物落 `ObjectStore`，按需由 `write_file` 注入容器。

### 2.6 exec 执行管线

```python
async def exec(self, argv, *, cwd, env, timeout_s, output_cap):
    # 1. env 白名单过滤（仅 PATH/LANG/工具声明变量；禁传凭证——凭证永不进容器）
    # 2. aiodocker exec 创建 + start（binary 协议 demux stdout/stderr）
    # 3. 流式捕获至 output_cap，超出置 truncated 并继续丢弃（进程跑完自然退出，防管道背压死锁）
    # 4. asyncio.wait_for(timeout_s)；超时 → kill exec → 若 5s 未退则容器 stop/start（会话级自愈）
    # 5. ExecResult(exit_code, stdout, stderr, truncated, duration_ms)
```

超时/失联（容器失联 = exec 创建抛错）→ 网关侧转 `is_error` 回执 + `ui={sandbox_error}`（[后端设计 §7.1 异常表](后端设计.md)），run 继续由模型决策改道。

### 2.7 镜像与 jail

- 基底 `debian:bookworm-slim` + `python3.12`、`node20`、coreutils、`ripgrep/fd/jq`；全部二进制属 root 可读、工作目录属 uid 1000；
- **jail 包装器**（`/usr/local/bin/jail`）：bash 工具的实际入口——`jail <cmd...>` 校验 argv[0] 在允许清单、拒绝 `sudo/su/chmod/setcap` 等提权与路径二进制、以 `env -i` 最小环境执行；读文件类工具（read_file/grep/glob）直接 argv exec，不经 shell；
- 镜像按月重建（基线更新），digest 记录进 `runs` 审计（sandbox_image 字段已预留）。

### 2.8 测试矩阵

| 用例 | 断言 |
|---|---|
| 越界路径 `../../etc/passwd` | resolver PathEscape → DENY 回执，容器零 IO |
| `curl https://...` | 网络禁用 → 命令失败回执（模型可改道） |
| `:(){ :|:& };:` fork 炸弹 | pids-limit 触发，容器存活，宿主无感 |
| 512MB 内存分配 | cgroup OOM 杀进程，exec 返回非零，容器存活 |
| 1MiB+ 输出 | truncated=True + spill 产物 URI 回执 |
| 超时 sleep 1h | timeout_s 杀 exec，回执 `timed out` |
| 会话空闲 11min | 容器 stopped；下一调用自动 start |
| worker kill 后 | 容器仍在（labels 清扫可回收），新 run 复用 |
