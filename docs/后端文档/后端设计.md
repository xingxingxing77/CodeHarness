# 后端设计

> 逐模块后端设计。现有代码位置以仓库根扁平布局为准；冒烟入口均可直接运行验证。
> 关联：[整体架构](../项目架构/整体架构.md) · [接口契约](../接口文档/接口契约.md) · [数据库设计](../数据库设计/数据库设计.md)

## 1. engine/ —— LangGraph 编排（已实现）

### 1.1 State 与消息模型

- `engine/types.py`：`AgentState(TypedDict)`——`messages`(自定义 reducer，支持 `ReplaceMessages` 哨兵整体替换)、`turn`、`effective_max_tokens`、`route`、`reactive_compact_done`、`pending_plan`、`usage_total`、`session_state`、`error`。
- `engine/messages.py`（现仓库根 `messages.py`，P0 迁入）：`PlatformMessage(role, content[4 类内容块], metadata)`——Text/Image/ToolCall/ToolResult 块，Anthropic 风格为"内部普通话"。
- 不变式 I-A1：State 内不出现框架类型；I-A2：与 messages 表轮次边界一致；I-A3：每个 tool_call 必有配对回执。

### 1.2 节点（`engine/nodes/`，8 个）

| 节点 | 职责 | 关键语义 |
|---|---|---|
| preprocess | 非视觉模型图片降级 | 并发图转文，`ReplaceMessages` 原地替换 |
| compact | 事前/反应式压缩 | 反应式由 `route=reactive_compact` 进入并 force，置 `reactive_compact_done`；压缩不回写表（run 内视图） |
| agent | 一次流式模型调用 | 重试下沉内核；异常按**类型**路由（`clamp_retry`/`reactive_compact`/`fail`）；空回复保护；轮次预算熔断（有 tool_calls 且超 `max_turns` → fail） |
| tools_prepare | 网关闸门①②③ | 纯检查无副作用，产出 `ToolPlan(auto_run/need_approval/refused)` |
| tools_approval | 审批挂起 | **全图唯一 interrupt 点**；重放幂等建单；未覆盖调用 fail-closed |
| tools_execute | 网关⑤+收尾 | 唯一副作用入口；按 `plan.order` 装配回执（缺失兜底，I-B2）；无挂起能力 |
| recover | 钳制重试 | clamp 不耗轮，复位 route 回 agent；reactive 透传 compact |
| finalize | 收敛出口 | STOP 类策略 hook + `run_finished` 事件 |

### 1.3 图装配（`engine/graph.py`）

```
START→preprocess→compact→agent─┬─proceed(有工具)→tools_prepare─┬─需审批→tools_approval→tools_execute─┐
                               ├─clamp_retry/reactive→recover─┴─无需审批→tools_execute            │
                               └─fail/收敛→finalize→END                                           │
                               └──────────────下一轮(preprocess)◄─────────────────────────────────┘
```

- 3 个纯路由函数：`route_after_agent`（只看 route 与有无 tool_calls）、`route_after_prepare`、`route_after_recover`。
- `run_graph()` 注入 `recursion_limit` 保险丝：`6×(max_turns+recover_extra)+10`；业务轮次权威判定在 agent 节点。
- `engine/serde.py`：平台类型白名单序列化器（`LANGGRAPH_STRICT_MSGPACK` 严格模式通过）。

### 1.4 预算（`engine/budget.py`）

`TurnBudget(max_turns, recover_extra=8)`；`bounded_completion_tokens(max_tokens, context_window)` 钳制 128k。

## 2. services/ —— run 生命周期（runner 已实现，P0 迁入）

`engine/runner.py` → `services/runner.py`：

- `RunJob(run_id, session_id, tenant_id, kind=new|resume, resume)`；
- `RunWorker.execute()`：**会话锁**（抢不到→重投让位）→ 写穿指针初始化为 store 历史长度（resume 补缺口）→ `astream(["values","custom"])` 双通道 → custom 翻译为 SSE 契约④发布 / values 驱动写穿 diff + `__interrupt__` 提取发布 `approval_required` → 收尾落 `session_state`/usage/终态；
- 基建协议 `RunQueue`/`RunLock`/`EventPublisher`：InMemory 实现 + Redis 薄封装（Streams 消费组 `XREADGROUP`、`SET NX EX` 锁、`XADD events:{session}`），联调在 P2；
- `engine/persistence.py` → `services/session_storage.py`：`MessageStore`/`SessionStore` 协议 + 内存实现；**表 → Stream 顺序**（先落事实源再发事件）。

## 4. tools/ + gateway —— 工具系统与执行网关

### 4.1 契约（已实现：`gateway/types.py`，P0 拆入 `tools/base.py` + `state/`）

- `ToolCall(id,name,input)` / `ToolResult(tool_use_id, content, is_error, ui, metadata)` / `UiPayload`（ui 通道永不进模型）；
- `ToolPlan(order, auto_run, need_approval, refused)` 两段式：`plan()` 纯可重放；`run()` 唯一副作用入口且**永不 raise**（I-B1）；
- `SessionState`（`gateway/session_state.py`）：类型化工作记忆，LRU 桶（goals/recent_files/artifacts/verified_work/work_log/async_tasks），失败不记。

### 4.2 五闸门管道（P1 实体化，`gateway/pipeline.py`）

```
① 策略(permissions/policy) → ② 查找(registry) → ③ pydantic 校验 → ④ 权限(路径归一+动态只读+裁决/审批) → ⑤ 沙箱执行 → 收尾 ABC(offload 卸载 / carryover 记账 / post hook)
```

- **唯一路径解析器** `resolver.py`：`file_path/path/root` 字段探测 → expanduser → 沙箱根内 realpath（越界=PathEscape）；权限与执行共用；
- 五类失败（hook 拦/未知工具/参数非法/权限拒/用户拒）全部转 `is_error` 回执喂回模型，协议闭环永不破；
- 大输出卸载：超预算落对象存储，回执给"完整 URI+预览+原始大小"供模型回读。

## 5. permissions/ —— 策略与审批

- `permissions/approval.py`（已实现，P0 自 gateway 迁入）：`ApprovalService`——幂等建单（键=`hash(run_id, sorted(call_ids))`）、决策记录（重复决策不覆盖）、30min TTL 过期转 expired（按 deny 恢复，run 永不无限挂起）；`payload_for()` 是 interrupt 载荷唯一来源；
- 策略引擎（P1）：租户规则表——工具白名单、路径围栏（匹配已绝对化的 resolved path）、命令 allow/denylist、只读自动放行（`is_read_only(parsed_input)` 按输入动态定级）。**实现细节（决策流/匹配顺序/三配方/DDL/测试矩阵）→ [权限与沙箱设计](权限与沙箱设计.md) §一**。

## 6. sandbox/ —— Docker per-session（P1）

- `SandboxHandle`（契约⑦）：session 级容器，非 root、`--network none`、工具二进制全 jail；
- worker 按 session 懒创建/空闲回收；执行经 `exec`，输入输出走 stdio；文件操作限定挂载工作目录内。
- **实现细节（威胁模型/容器规格/路径映射/exec 管线/镜像 jail/测试矩阵）→ [权限与沙箱设计](权限与沙箱设计.md) §二**。

## 7. compact —— 三层上下文防御（P2 实体化）

- 事前：每轮 `compact` 节点按 `Compactor.estimate` 超阈值压缩（microcompact 清老 tool_result → LLM 摘要，摘要注入 SessionState 作 carryover）；
- 事后：`ContextOverflowFailure` → 反应式压缩 force 一次（`reactive_compact_done` 防震荡，二次直接 fail）；
- 旁路：`max_tokens` 主动钳制 + 厂商报错解析动态下调（clamp 不耗轮）。
