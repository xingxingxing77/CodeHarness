# 配置清单

> 全部环境变量的单一真相源。原则：**环境变量只在装配层读取**（server/worker 启动入口），引擎与网关内部一律构造注入（`EngineConfig`/`GatewayConfig`）；`.env` 不入库，密钥走密钥管理。

## 2. 密钥管理原则

1. 🔴 三类（JWT_SECRET / CREDENTIAL_MASTER_KEY / 供应商 key）不入库不入镜像；本地放 `.env`（gitignore），生产走 KMS/secret manager；
2. 供应商凭证的**平台正源**是 `credentials` 表（写即 AES-GCM 加密）；env 供应商 key 只用于开发直连与 ClientFactory bootstrap，租户凭证解析优先级：会话指定凭证 → 租户 `credentials` → bootstrap env；
3. 轮换：`CREDENTIAL_MASTER_KEY` 支持双密钥过渡（新写旧读）；JWT_SECRET 轮换 = 全员重登（可接受）。

## 3. 配置加载方式

- **P2 起**：装配层用 `pydantic-settings` 定义 `AppSettings`，按模块拆 `redis_dsn / database / sandbox / object_store / auth` 子组；测试用 `AppSettings()` 默认值即不依赖 env；
- **引擎/网关**：永远只见 `EngineConfig`/`GatewayConfig` 数据类（`engine/deps.py`），不 import settings——保证节点可脱离装配层独立驱动（冒烟即证）；
- 新增变量的流程：本表登记（含阶段与密级）→ 装配层读取 → 对应模块文档同步。
