# 整体架构

> 多租户 Agent 平台：LangChain/LangGraph 编排 + FastAPI（REST+SSE）+ Redis（队列/事件/锁）+ Postgres+pgvector（事实源/记忆）+ Docker per-session 沙箱。

## 二、一次用户输入的全链路（时序）

```
浏览器            FastAPI            Redis            RunWorker            LangGraph 引擎
  │ POST /sessions/{id}/messages        │                 │                    │
  ├──────────►│ 校验 JWT/租户           │                 │                    │
  │           ├ XADD run:queue ───────► │                 │                    │
  │ ◄─202 {run_id}─┤                    │                 │                    │
  │           │ SSE 订阅 events:{sid}   │ XREADGROUP ────►│                    │
  │           ├──────────────────────► │◄ acquire lock ──┤                    │
  │           │                        │  astream(values,custom) ──►│ 图执行   │
  │           │                        │                 │   agent→api 内核→流式 delta
  │ ◄═assistant_delta(SSE)═════════════╗ │ ◄─custom 事件──┤   prepare→权限裁决  │
  │           │                        │ ◄─XADD events──┤   需审批→interrupt 挂起
  │ ◄═approval_required════════════════╗│                │   （图暂停，checkpoint 落库）
  │ [用户在审批卡点批准]                   │                 │                    │
  │ POST /runs/{rid}/approvals/{tid}/decide│                │                    │
  │           ├─写工单+XADD resume─────► │ ─resume job───► │ Command(resume) 续跑│
  │           │                        │                 │   execute→沙箱→回执  │
  │ ◄═tool_started/tool_completed══════╗ │ ◄──────────────┤   循环至无 tool_calls │
  │ ◄═run_finished(usage)══════════════╝ │ ◄─写穿 messages 表──┤ finalize        │
```

要点：审批可在**任意设备**完成（决策=写表+入队，任意 worker 续跑）；kill worker 后锁过期，新 job 以同一 thread_id 从 checkpoint 恢复。

## 四、部署拓扑

| 进程 | 职责 | 横向扩展 |
|---|---|---|
| web (Next.js) | 静态资源 + BFF 代理 | 无状态，随意扩 |
| server (FastAPI, uvicorn) | REST + SSE 网关 | 无状态，随意扩 |
| worker ×N | 消费 run 队列、执行图 | 按队列深度扩；会话锁保证同会话串行 |
| redis | 队列/事件流/锁/幂等 | 哨兵或集群；**不做业务存储** |
| postgres | 事实源 + checkpoint + pgvector | 主从；checkpoint 表可独立清理 |
| sandbox 容器 | per-session 工具执行 | 由 worker 动态创建销毁 |

## 五、关键架构决策

1. **messages 表是事实源**：LangGraph checkpoint 只承担 run 内挂起/恢复，可丢弃可重建；`thread_id = run_id`（一 run 一线程）。
2. **框架类型防火墙**：LangChain/LangGraph 类型止步于 `engine` 编排层内部；SSE 事件（契约④）、消息模型、工具定义均为平台自定义类型，边界显式转换。
3. **双通道事件**：`astream(stream_mode=["values","custom"])`——custom 通道翻译为 SSE（契约④），values 通道驱动写穿 diff 与 `__interrupt__` 提取。
4. **写穿顺序 = 表 → Stream**：先落 Postgres 再发 `assistant_turn_complete`，SSE 重放永不超前于事实源。
5. **审批是唯一挂起点**：工具段拆 prepare/approval/execute 三节点，interrupt 重放只幂等建单，副作用只在 execute。
6. **ToolResult 双通道**：`content` 进模型上下文（token 受控、可卸载为引用），`ui` 给前端（diff/终端卡片，永不进模型）。
7. **沙箱即边界**：所有工具执行只经 `SandboxHandle`（非 root、--network none、路径全 jail）；权限裁决与执行共用唯一 path resolver。
8. **错误分类下沉内核**：`AuthenticationFailure/RateLimitFailure/ContextOverflowFailure/RequestFailure` 四类统一异常树；引擎按类型路由，不做文本嗅探。
