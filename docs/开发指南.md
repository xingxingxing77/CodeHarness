# 开发环境与启动指南

> 怎么把本项目跑起来。设计态文档见 [README](README.md) 导航；本文只管**动手**。
> 环境：Windows（本仓库开发机）· Python 3.13 · Node 24（前端 P2 起用）· Docker Desktop（P1 沙箱起用）。

## 1. 目录约定（仓库根即导入根）

```
G:\Codeharness\
├── api/ engine/ gateway/ tools/ messages.py   # Python 包，import 前缀 = 目录名（engine.xxx）
│   │               # api/ = 供应商内核（已搬迁）；tools/ = 五内置工具
├── docs/                # 设计文档（本目录）
├── tests/               # tests/api/ 内核测试（pytest，86 用例）
└── server/ web/         # P2 新建
```

**红线**：顶层包永远不叫 `platform`（遮蔽标准库，anthropic/openai SDK 导入即崩）；框架（langchain/langgraph）类型不进 `engine` 编排层以外（见 [设计计划 §五](设计计划.md)）。

## 2. 安装

```bash
cd G:\Codeharness
python -m pip install "langgraph>=1.2" "langchain-core>=1.6" "pydantic>=2.13" redis anthropic openai pytest pytest-asyncio
# P1 追加：aiodocker          # Docker 沙箱实现（FakeSandbox 冒烟不需要）
# P2 追加：fastapi uvicorn asyncpg "pgvector" pydantic-settings python-jose
```

版本策略：langgraph/langchain-core 锁小版本（API 波动防护墙）；升级 = 改 pydantic 约束 + 全量冒烟。

## 3. 本地基建（P2 联调起用，冒烟不需要）

`docker-compose.yml`（仓库根，P2 提交）：

```yaml
services:
  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]
  postgres:
    image: pgvector/pgvector:pg16        # 自带 vector 扩展
    environment:
      POSTGRES_PASSWORD: codeharness
      POSTGRES_DB: codeharness
    ports: ["5432:5432"]
    volumes: [pgdata:/var/lib/postgresql/data]
volumes: { pgdata: {} }
```

启动：`docker compose up -d`；Postgres DDL 见[数据库设计](数据库设计/数据库设计.md)（P2 起用 alembic 管理）。

## 4. 冒烟验证（每步改动后的回归底线）

```bash
python -m pytest tests/api -q   # api 内核测试 86 用例（供体迁移 + 解耦适配）
python -m engine.smoke          # 节点级 7 用例
python -m engine.smoke_graph    # 图级 5 用例（MemorySaver）
python -m engine.smoke_runner   # runner 端到端 3 用例
python -m tools.smoke_tools     # 工具级 6 用例（resolver/五工具/回执）
```

严格模式（等价生产 checkpointer 行为）：

```bash
set LANGGRAPH_STRICT_MSGPACK=true && python -m engine.smoke_graph
```

全绿 = 106 用例通过。**全部由 Fake 驱动**（`engine/testing.py` 的 FakeChat/FakeGateway/FakeSandbox 等），不需要真实供应商 key、不需要 Redis/Postgres/Docker——这是刻意设计：基建联调问题与逻辑问题分离（联调用例 P2 引入）。

## 5. 开发流程（接口先行）

1. 动代码前核对：接口是否已有契约（[接口契约](接口文档/接口契约.md)、各后端设计文档）；
2. 接口变更：先改契约文档 → 冒烟/测试锁定 → 再改实现；**否决**直接改代码绕过契约；
3. 决策级取舍（换方案、换依赖）记入 [设计计划 §五](设计计划.md) 关键决策，不散落代码注释；
4. 提交前跑三套冒烟；涉及 checkpoint 序列化的改动加跑严格模式。

## 6. 已知坑（踩过的）

| 坑 | 现象 | 规避 |
|---|---|---|
| 顶层包名 `platform` | anthropic/openai SDK 崩溃 | 永不用该名（已定 codeharness 拍平布局） |
| LangGraph 未注册类型 | checkpoint 反序列化警告，未来直接阻断 | 新平台类型必须进 `engine/serde.py` 白名单 |
| interrupt 恢复重跑节点 | 工具执行两次 | 挂起点只允许在 tools_approval 节点（S3 不变式） |
| 写穿指针从 0 起 | 初始历史重复落库 | 指针=store 历史长度（runner 已修，改动需回归 smoke_runner） |
| pydantic 模型位置参数 | `UsageSnapshot(1,1)` TypeError | 平台 pydantic 类型一律关键字构造 |

## 7. 代码级配置入口

引擎运行时配置不经环境变量，走注入：`EngineConfig` / `GatewayConfig`（`engine/deps.py`）由 server/worker 装配层构造——环境变量只在装配层读取，清单见[配置清单](配置清单.md)。
