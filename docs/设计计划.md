# 设计计划：OpenHarness 目录对齐 + 技术栈替换

> 目标：目录结构 1:1 对齐供体库 E:\OpenHarness 的 20 个模块（7.1 api ~ 7.20 cli.py），底层替换为本项目技术栈（LangChain/LangGraph 编排、FastAPI REST+SSE、Redis 队列/事件/锁、Postgres+pgvector 存储、Docker per-session 沙箱），弱项增强、缺口补齐。

## 三、施工方法论：解耦 → 契约 → 替换 → 验收

每个模块统一四步，**解耦与替换严格分开**：

1. **解耦（脱供体）**：切断对供体特有模块的依赖（Settings/本地文件/auth.external/单例），依赖全部构造注入；不动业务逻辑，冒烟基线全绿。
2. **契约冻结**：Protocol/dataclass 接口定稿，行为用冒烟锁定。
3. **替换/增强**：新技术栈落地到契约后面，契约不变。
4. **验收**：契约测试 + E2E。

**样板：api/ 层解耦清单**：
- 删 `provider.py`（依赖 Settings 的诊断）；`__init__` 惰性导出；
- 删/抽 `claude_oauth` 路径（对 auth.external 的依赖）；
- `copilot_auth` 本地文件存储改为 TokenStore 注入；
- 客户端选型改注册表驱动 ClientFactory（替换 5 分支 if）；
- 新增 `ContextOverflowFailure` 归一（替代 prompt-too-long 文本嗅探）。
- 之后"替换框架" = 经 `OpenHarnessChatModel` 适配器桥接进 LangGraph，内核保留（Codex/Copilot 通道无现成 LangChain 集成）。

同法：tools/ 先脱 BaseTool 继承树改自有 ToolDef 再接 LangChain @tool；memory/ 先收敛 MemoryStore 协议再落 pgvector；hooks/ 先抽 HookRunner 协议再换 Redis 事件总线。

## 五、关键设计决策

1. **框架类型防火墙**：LangChain/LangGraph 类型止步于编排层三个文件（agent/tools_execute/graph）；SSE 契约、消息模型、工具定义均为平台自定义类型。
2. **messages 表是事实源**：checkpointer 可丢弃可重建（反之不行）；恢复时以表校验图状态。
3. **循环终止只看有无 tool_calls**，不信 stop_reason（供应商词汇表不可靠，仅作 UI 提示）。
4. **重试只在 LLM 层**（内核 4 次、1→30s 指数退避+抖动、认证错误永不重试）；工具错误喂回模型不自动重试。
5. **审批异步工单化**：LangGraph interrupt + Postgres 工单 + Redis 通知，跨进程/设备恢复，30min TTL 超时按 deny。
6. **工具段拆三节点**：prepare(纯)/approval(唯一 interrupt)/execute(副作用)，防 interrupt 重放双执行。
7. **checkpointer thread_id = run_id**：一次 run 一个线程，历史从 messages 表加载。
8. **ToolResult 双通道**：content 给模型（token 受控），ui 给前端（永不进模型上下文）。
9. **路径单一解析器**：权限裁决与沙箱执行共用 resolver，杜绝两套解析的绕过面。
