# 部署与运维

> 项目怎么运行：本地最小运行 → 生产拓扑 → 迁移 → 监控告警 → 备份恢复 → 故障手册（runbook）。
> 关联：[整体架构 §四 部署拓扑](../项目架构/整体架构.md) · [配置清单](../配置清单.md)（全部 env） · [数据库设计](../数据库设计/数据库设计.md)（DDL） · [开发指南](../开发指南.md)（冒烟）
> 阶段标注：本文描述目标运行形态；标 **[P2]** 的组件在 P2 落地前不存在，当前（P0/P1）可运行的是冒烟体系与引擎库（见 §二.1）。

## 一、运行形态总览

| 进程 | 启动方式 | 端口 | 依赖 | 可副本数 |
|---|---|---|---|---|
| web [P2] | `pnpm start`（Next.js） | 3000 | server | N |
| server [P2] | `uvicorn server.app:app --port 8000` | 8000 | redis, postgres | N（无状态） |
| worker [P2] | `python -m server.worker` | — | redis, postgres, docker | N（会话锁保证同会话串行） |
| redis | compose / 托管 | 6379 | — | 1（哨兵/集群可选） |
| postgres | compose / 云 RDS | 5432 | — | 1 主 + 备 |
| sandbox 容器 [P1] | worker 按 session 动态创建 | 无（--network none） | — | ≤ 并发会话数 |

一条请求的路径：浏览器 → server（POST /messages 入队）→ redis `run:queue` → worker 抢会话锁执行 LangGraph 图 → api 内核 / sandbox 容器 → 事件 XADD `events:{session}` → server SSE 网关 → 浏览器。

## 二、本地运行

### 2.1 当前阶段（P0/P1）：引擎冒烟即运行

```bash
python -m pip install "langgraph>=1.2" "langchain-core>=1.6" "pydantic>=2.13" redis
python -m engine.smoke && python -m engine.smoke_graph && python -m engine.smoke_runner
```

三套 15 用例全绿 = 引擎可运行。**不需要** redis/postgres/docker/供应商 key（Fake 驱动，见[开发指南](../开发指南.md)）。

### 2.2 本地全栈 [P2]

```bash
# 1. 基建
docker compose up -d                          # redis + postgres(pgvector)
# 2. 建库（DDL 权威=数据库设计；checkpoint 表由 langgraph setup() 建）
python -m server.db.setup                     # 执行 DDL + AsyncPostgresSaver.setup()
# 3. 准备 .env（最小集）
#    DATABASE_URL=postgres://postgres:codeharness@localhost:5432/codeharness
#    REDIS_URL=redis://localhost:6379/0
#    JWT_SECRET=<32B 随机>   CREDENTIAL_MASTER_KEY=<32B base64>
#    ANTHROPIC_API_KEY=<dev 直连>            # 或在凭据页录入
# 4. 起三个进程（三个终端）
python -m server.worker                       # run 消费者
uvicorn server.app:app --reload --port 8000   # REST + SSE
pnpm dev                                      # web（web/ 目录）
# 5. 端到端验证
curl -X POST localhost:8000/api/v1/sessions -H 'Content-Type: application/json' \
  -d '{"model":"claude-sonnet-4-6"}'
curl -N localhost:8000/api/v1/sessions/{sid}/events &     # 先挂 SSE
curl -X POST localhost:8000/api/v1/sessions/{sid}/messages -d '{"content":[{"type":"text","text":"hi"}]}'
# 期望 SSE 序列：assistant_delta* → tool_started/completed → run_finished
```

## 三、生产部署

### 3.1 单机 compose（≤ 数十并发会话）

在 2.2 基础上生产化：`restart: unless-stopped`、healthcheck（server: GET /healthz；worker: 心跳 key 检查）、数据卷持久化（pgdata）、`.env` 外置、`worker` 用 `deploy.replicas` 或 `docker compose up --scale worker=4` 扩容。前置 Caddy/nginx 终结 TLS——**SSE 两项必须配置**：`proxy_buffering off`、`proxy_read_timeout 300s`（长连事件流）。

### 3.2 k8s 提要（规模化）

- Deployment ×3：server（HPA 按 CPU）、worker（**KEDA 按 redis 队列深度伸缩**，`XLEN run:queue + pending`）、web；
- Redis：哨兵或云托管；Postgres：云 RDS + pgvector 扩展（备份/HA 交给云）；
- worker 节点需挂 docker socket 或 DinD sidecar 以管理沙箱容器（或改用 sysbox 运行时）；
- 沙箱镜像推送私有仓库，digest 固定（runs.sandbox_image 审计）；
- 所有 🔴 密钥走 secret manager（配置清单 §2），不进镜像。

### 3.3 升级与回滚

1. 顺序：**DB 迁移先上**（只做向后兼容迁移：新列可空/带默认）→ worker 滚动 → server 滚动 → web；
2. 回滚 = 镜像回退；**迁移不回滚**（向前修复：再加一列/视图适配）；
3. SSE 契约事件只增不改（前端按 type 分发，未知 type 必须忽略——前后端共同约定）。

## 四、数据库迁移

- 工具：alembic；DDL 变更的权威来源是[数据库设计](../数据库设计/数据库设计.md)，迁移脚本与其同步评审；
- `AsyncPostgresSaver.setup()` 独立于业务迁移执行（checkpoint 表结构由 langgraph 管理，随依赖版本升级检查 release notes）；
- 迁移窗口：worker 缩到 0 → 迁移 → 滚动升级 → worker 扩回（会话锁与队列保证中途 run 不丢：interrupted/pending 均可恢复）。

## 五、监控与告警

### 5.1 指标（server/worker 暴露 /metrics，Prometheus 抓取）

| 指标 | 来源 | 告警建议 |
|---|---|---|
| `run_queue_depth`（XLEN + pending） | redis | > 50 持续 5min → 扩 worker |
| `worker_heartbeat_age` | 锁/心跳 key | 任一 worker > 15s 失联 → 告警 |
| `runs_{status}_total`（速率） | runs 表/计数器 | failed 率 > 10%/10min → 告警 |
| `run_duration_p95` | runs.finished_at-created_at | 超 10min → 关注（配合 SLO） |
| `approvals_pending` | approvals 表 | 持续增长 → 审批积压（运营侧） |
| `sandbox_containers`（docker labels 计数） | worker | 超过 会话数×1.5 → 泄漏，跑清扫 |
| `sse_connections` | server | 容量水位 |
| `usage_tokens_total{tenant}` | runs 表 | 租户配额预警（M3） |

### 5.2 日志

结构化 JSON（`run_id/session_id/tenant_id` 三键贯穿全链路）；沙箱容器 `--log-driver none`（输出只走 exec 捕获，避免双写）；audit_events 表承接权限决策与 hooks 事件的持久尾迹。

## 六、备份与恢复

| 数据 | 策略 | 恢复定位 |
|---|---|---|
| Postgres | 每日全量 pg_dump + WAL 归档（PITR） | **messages/runs/approvals 是事实源，必须恢复** |
| checkpoints 表 | 随 PG 备份，但**可丢弃** | 丢则从 messages 表重建图状态（thread_id=run_id 重放） |
| redis | 不备份 | 队列 pending 由 watchdog 重投；events 流历史可弃（回放走 GET /messages） |
| 对象存储（spill 产物） | 版本化桶 | URI 在 tool_result 里，必须与表同存 |
| 凭证表 | 密文随 PG 备份；`CREDENTIAL_MASTER_KEY` **独立托管**（与备份分离存放） | 丢主密钥 = 凭证不可解，需全员重录 |

**季度演练**：恢复 PG 到隔离环境 → 校验 messages 完整 → 丢 checkpoint 重建图 → resume 一个 interrupted run → 对比事件流无缺口。演练脚本与断言清单 P3 提交 `ops/drill/`。

## 七、故障手册（Runbook）

| 症状 | 诊断 | 处置 |
|---|---|---|
| run 长期 `queued` | `XLEN run:queue`↑ 且无 worker 心跳 | worker 挂 → 重启/扩容；队列堆积 → `--scale worker` |
| run 卡 `running`（worker 进程消失） | 锁 key 仍在但心跳过期 | 等 `RUN_LOCK_TTL_S`(30s) 过期 → watchdog 扫 `running/interrupted` 重投 → 同 thread_id 从 checkpoint 续跑，**无需人工**；持续卡 → 查 worker 日志 OOM |
| run 卡 `interrupted` 无人批 | approvals 表 pending + expires_at | 等 TTL 到期自动 deny 恢复（run 不死）；紧急可手动 `decide` |
| SSE 断流不续 | 浏览器 Last-Event-ID 未生效 | 检查代理是否剥 `Last-Event-ID` 头 / `proxy_buffering off`；服务端 XREAD `after` 游标 |
| 事件重复 | Stream MAXLEN 裁剪过 | 前端按 `(event id)` 去重；确认 MAXLEN ~10000 配置 |
| 沙箱容器泄漏（数量异常） | `docker ps --filter label=codeharness.tenant` | 跑清扫：按 labels 删除无主容器（watchdog 每 10min 自动一次） |
| 沙箱 exec 全部失败 | 容器创建报错 | 磁盘满/镜像缺失；`sandbox_unavailable` 回执已喂模型，修基础设施即可 |
| 供应商 401 面广 | api 审计 `AuthenticationFailure` | credentials 表轮换该 provider 凭证（写即加密）；env bootstrap key 同步换 |
| PG 连接耗尽 | `pg_stat_activity` | 池大小 vs (server+worker)×pool 上限；RDS max_connections |
| 严格 msgpack 启动报类型未注册 | 新 state 类型未白名单 | 加进 `engine/serde.py` 再发布（开发指南已知坑） |

## 八、容量参考（初始基线）

单 worker（4C8G）：并发 run ~8（受沙箱内存 512m×N 与 api 并发限制）；每 run 平均 20 轮 ≈ 200k tokens。队列深度 > worker 数×8 持续 5 分钟即触发 KEDA/手动扩容。PG 起步 2C8G/100G（WAL 含在内），messages 增长按 ~4KB/条估算。
